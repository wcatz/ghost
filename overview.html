Top features

Everything a memory system should do. Nothing you have to run.

Most memory products make you choose between a hosted silo and a self-hosted stack of Postgres plus a vector database. Ghost packs the whole pipeline into one static binary.

Search

Hybrid vector + full-text

SQLite FTS5 and local Ollama embeddings fused with Reciprocal Rank Fusion (70/30). Falls back gracefully to FTS-only when embeddings aren't available — no error, no setup step.

Structure

Eight memory categories

architecture, decision, pattern, convention, gotcha, dependency, preference, fact — enforced by a database constraint, weighted by importance, deduped on save.

Freshness

Category-aware time decay

Conventions and preferences never fade; stale gotchas do. Superseded facts are demoted below their replacements, so agents stop acting on outdated state.

Lifecycle

Resolve & supersede

Resolved evidence drops out of ranked injection but stays searchable. Update chains (v1→v2→v3) rank correctly. Writes are dry-run by default and require explicit --apply.

Consolidation

Reflect, with guardrails

Optional LLM consolidation merges near-duplicates — with an empty-set guard and pinned-memory protection, plus a fully offline Jaccard tier when no API key is present.

Scope

Cross-project & global

One memory across every repository and every MCP client. Project-scoped recall, cross-project search, and a _global project for preferences that follow you everywhere.

Graph

Auto-linked memory graph

Similar memories link automatically (cosine ≥ 0.70) and mirror into an Obsidian vault — browse your project's knowledge as a graph, not a log.

Portability

Any MCP client

Standard MCP over stdio. Claude Code, Cursor, Goose, opencode, or anything else that speaks MCP — point it at the binary and Ghost's tools and context injection go live.

Operations

Zero-infrastructure ops

One binary, one SQLite file, no daemon — Ghost runs only when your client spawns it. Prebuilt binaries for linux/macOS/Windows, amd64/arm64, Docker multi-arch, one-command Windows installer.

For companies

Built for environments where "just trust us" isn't an answer.

Cloud memory services mean your codebase's context — architecture decisions, credentials-adjacent gotchas, internal hostnames — sits on someone else's servers, metered per request. Ghost was designed so the security review ends quickly: there is simply no channel for data to leave.

Data residency by construction

All memories live in one SQLite file under your own home directory. There is no cloud tier, no sync, no account, and no telemetry. Your agents' knowledge never crosses your network boundary — which makes GDPR/CCPA data-mapping trivial: the entire processing location is a path you own.

Auditable, enumerable egress

In normal operation Ghost makes zero network calls. There are exactly three exceptions, all opt-in and documented: localhost Ollama for embeddings, the Anthropic API only if you enable LLM consolidation, and the GitHub API only for self-upgrade. That is the complete list — verifiable in an afternoon of code review, not promised in a DPA.

Inspect what your agent sees

The exact context injected into every session is a bounded digest you can print with one command. No mystery blob in the system prompt — what enters your LLM vendor's logs is knowable in advance, which is precisely what AI-governance reviews ask for and cloud memory can't show.

Deterministic retention & deletion

Deletion is real: remove the data directory and the memory is gone — no provider-side replica, backup window, or retention policy to negotiate. Lifecycle operations (resolve, supersede, consolidation) are dry-run by default and apply only with an explicit flag, so every destructive action has an owner.

No lock-in, honest exit

Memories live in a plain SQLite file whose schema is a readable constant in the repo. Query it with sqlite3, back it up with cp, read it with anything. If Ghost disappears tomorrow, the data outlives the tool — procurement calls this "acceptable," auditors call it "portable."

Least privilege by default

Subagent sessions receive nothing injected (they inherit context in-band from the parent), resume sessions skip injection, and compaction emits a pointer instead of re-dumping content. Memory exposure is scoped to the interactive sessions that asked for it.

Reproducible evaluation

Every published number ships with its harness, dataset, seeds, and per-question logs — deterministic, judge-free retrieval scoring included. When compliance asks "how was this measured," the answer is a command anyone can run, not a screenshot of a vendor dashboard.

Small supply chain

One static Go binary, pure-Go SQLite (no CGO), checksums published per release, Apache-2.0 licensed. No containers to patch, no Postgres to harden, no sidecar services in your threat model — because there are no other services.

Own your data

The strongest compliance control is not having a vendor.

Cloud memory platforms earn trust the traditional way: audit reports, DPAs, subprocessor lists, and a trust center you review before signing. Mem0's, for example, shows SOC 2 Type I achieved with Type II and GDPR work in progress — a normal, credible posture for a SaaS vendor. But every one of those artifacts exists to manage their access to your data. Own the data, and most of that machinery is simply not needed: there is no processor relationship to paper over, because nobody else holds anything.

The trust-center model

Cloud memory platform (e.g. Mem0 managed platform)
  • You must verifyVendor assuranceSOC 2 reports, penetration tests, ISO certificates — reviewed annually, NDA-gated, and always describing last quarter's controls.
  • They hold itData custodyYour agents' knowledge of your codebase, customers, and internals sits in their cloud, in regions they chose.
  • Their chainSubprocessorsHosting, logging, and support tooling each add a third party you didn't select and must track as they change.
  • On requestDeletion & retentionGDPR erasure means asking the processor and trusting their backup windows and replication lag.
  • Depends on themBreach responseYour incident timeline includes their detection time, their disclosure obligations, and their communication quality.
  • ContractualOngoing cost of trustDPA negotiation, security questionnaires, renewal-time re-review — plus enterprise pricing for audit logs and SSO.

The ownership model

Ghost — memory on infrastructure you already control
  • Nothing to verifyNo vendor access existsThere is no Ghost-side account, token, or endpoint that could reach your memories. The attack surface for "the vendor" is zero by construction.
  • You hold itData custodyOne SQLite file on company-managed hardware. Residency equals wherever IT put it — office, laptop fleet, or private VPC.
  • Your chain onlyNo subprocessorsNo third party touches memory data in normal operation. The complete egress list is three opt-in calls, documented and code-verifiable.
  • ImmediateDeletion & retentionDelete the file (or a row) and it's gone. Erasure is provable in seconds without anyone's ticket queue.
  • Yours aloneBreach scopeA compromised laptop exposes that laptop's data — same as any other local file. There is no multi-tenant blast radius.
  • One-timeCost of trustSecurity review reads one small Go codebase with an embedded schema. No DPA to negotiate; no renewal-time re-assessment.
Fair reading: certifications transfer trust cheaply, and self-hosting shifts obligations onto you — endpoint management, backups, and access control become your job. That trade is exactly why the next section exists.
For teams

What Ghost needs to win small and mid-sized businesses.

Today Ghost is a superb single-player product, and SMBs don't buy single-player — they buy team workflows with governance attached. The architecture is the hard part and it's done: storage, search, decay, and lifecycle all live behind one store interface. What follows is the honest gap list, sized for a 10–200 person company.

Deploy & share

  • Shared-team mode: a small server flavor of the existing store (same SQLite schema, Litestream-style replication) so a team shares org/project memories while individuals keep private stores.
  • Managed rollout: MDM-friendly packages and an org config file so IT ships ghost mcp init pre-configured instead of per-desktop setup.
  • Backup story: scheduled snapshots with a documented restore procedure — the file format already makes this trivial; productize it.

Control

  • Per-project ACLs: who may read vs write which project's memories — maps directly onto the existing project model, no schema redesign.
  • Encryption at rest: SQLCipher option or documented OS-disk-encryption posture (FileVault/BitLocker), stated plainly for the security questionnaire.
  • Retention policy engine: TTLs per category ("gotchas purge after 90 days") extending the decay system that already exists.

Prove

  • Append-only audit log: who saved, resolved, superseded, or deleted what — exportable as JSONL for the compliance review.
  • Compliance pack: a self-assessment mapping Ghost's properties onto SOC 2 CC-series and ISO 27001 Annex A controls, plus a signed SBOM for the single binary.
  • LTS releases + support tier: pinned long-support versions and a paid channel — the parts of "enterprise-ready" that are process, not code.

Day 1 — Provision

IT rolls out Ghost with MDM; nothing user-installed

The shared server runs next to the existing Git host; laptops point at it via org config. Endpoint disk encryption covers the local cache. Total new infrastructure: one static binary and one replicated file.

Week 1 — Seed

Tech lead loads institutional knowledge into _global

Coding conventions, architecture decisions, the staging-database gotcha — imported from existing docs or saved by hand. Every developer's agent starts its first session already knowing them, via ghost mcp init.

Ongoing — Operate

Agents remember as a side effect of working

Decisions, gotchas, and dependencies get saved during normal sessions; near-duplicates merge on save; weekly ghost reflect --apply consolidates; superseded facts demote automatically. Nobody fills in a wiki after the fact.

Quarterly — Govern

Compliance runs its cadence against files, not vendors

Review the Obsidian graph or query SQLite directly; export the audit log for the security review; verify backups restored; offboarding is deleting one engineer's store. No questionnaire goes to any vendor, because no vendor is in the loop.

Build on Ghost

One memory engine, many industries.

Ghost is Apache-2.0: anyone may take the engine and ship a vertical product on it — closed source, commercial, no royalties. The compliance posture that serves developers (data stays put, egress is enumerable) is exactly what regulated industries are asking for.

Healthcare

PHI never has to leave the building. A clinic-deployed memory server keeps patient-workflow knowledge — referral quirks, prior-auth gotchas, payer-specific rules — on premises, so no BAA is needed at the memory layer at all.

Position as HIPAA-ready architecture, never "HIPAA certified": residency by construction, append-only audit log for access reviews, retention TTLs aligned to record policies.

Hotels & hospitality

Guest preferences without a central PII honeypot. Each property or region holds its own store: room preferences, allergies, VIP notes surface to front-desk agents instantly — and a breach at one property isn't a breach of the whole chain.

Retention is a feature: category TTLs can age guest data out automatically to match privacy rules instead of accumulating it forever in a vendor cloud.

Legal & finance

Matter-scoped silos map onto Ghost's project model. Engagement-specific memory stays isolated per client matter — cross-project search stays an explicit, audited act rather than a background leak.

Freshness is defensibility: supersede-and-demote means an agent citing last year's filing deadline gets outranked by the current one, with the update chain preserved for review.

The license in one breath: Apache-2.0 grants commercial use, modification, redistribution, sublicensing, and a patent grant — closed-source derivatives are fine. Keep the LICENSE text and attribution notices, mark modified files. One thing it does not grant: the trademark. Vertical products need their own name (sensible regardless — "Ghost" is already a well-known publishing platform).
FAQ

The questions a security reviewer will ask anyway.

Short answers here; the code and documentation behind them live in the repo — start at the README and docs/benchmarks.md.

Where does my data actually go?
One SQLite file under ~/.local/share/ghost (or $XDG_DATA_HOME/ghost) — same path on every OS. In normal operation Ghost makes zero network calls. There are exactly three exceptions, all opt-in and documented: localhost Ollama for embeddings, the Anthropic API only if you enable LLM consolidation, and the GitHub API only for self-upgrade.
What exactly gets injected into my agent's context?
A bounded digest — project name, top memories, learned context, open tasks, active decisions. You can print the exact bytes your agent will see: echo '{"cwd":"'"$PWD"'"}' | ghost hook session-start. Subagent sessions get nothing (context flows in-band from the parent), resume skips injection, compact emits a one-line pointer.
How do I get my data out?
It's already out — that's the point. Plain SQLite: query it with sqlite3, copy it with cp, read the schema as a Go string constant in internal/memory/schema.go. No proprietary format, no export request form. Getting in is easy too: ghost mcp init imports existing Claude Code memories read-only.
Is there a real off switch?
Yes, at four levels: remove the MCP entry from your client config (Ghost only runs when spawned over stdio — there's no daemon); set embedding.enabled: false; consolidation never runs unless you invoke ghost reflect, and applies nothing without --apply; delete the data directory and everything is gone. There is nothing else.
What does it cost to run?
$0/month. No metered API sits in the hot path — search, save, decay, and injection are all local. The only paid call anywhere in the codebase is the optional Haiku consolidation tier, which has a fully offline fallback tier. Benchmark reproductions cost $3–24 per full run depending on generator+judge choice.
